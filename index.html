CI vs CD

Continuous Integration (CI)

Developers merge code changes into shared repo frequently. Each merge triggers automated build and test.

  • Catch bugs early
  • Avoid integration conflicts
  • Fast feedback to developers

Continuous Delivery (CD)

Code that passes CI automatically prepared for release. Deployment to production requires manual approval.

  • Release-ready builds always
  • Reduced deployment risk
  • Manual gate before prod

Continuous Deployment

Every change that passes automated tests deploys to production automatically. No manual step.

  • Fastest delivery speed
  • Requires strong test coverage
  • High automation trust

Quality

Automated tests catch bugs before they reach users.

Consistency

Same automated process every time. No manual drift.

Feedback

FAQ

What is a pipeline?
Sequence of automated steps that take code from commit to production.
Do I need containers for CI/CD?
No. Containers help consistency but pipelines work with any deployment target.
CI/CD vs DevOps?
CI/CD is practice within DevOps culture. DevOps is broader: culture, process, tooling.
